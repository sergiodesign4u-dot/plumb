Node 4.3, search results. The query stays in the field, the matches are listed, and the count line reads against the whole registry rather than against itself. The query also lives in the URL, so a result set is an address rather than a transient state, which costs nothing and makes it reproducible when somebody reports it. The row variant this node adds: when the match was in the definition text and not in the name, the row shows the matching fragment under the name, and otherwise it does not. Search reaching into the definition is the mechanism that closes R2, and a match the analyst cannot see makes the result look wrong. The no-match case is where a dead end would be cheapest to leave, so it carries a line saying there is no match, a line of advice, one reset action, and the primary action with the query already in it: searching for a metric that does not exist is the strongest available signal that it should exist, and a no-match in the analyst's own registry becomes the activation moment instead of an apology. The count says zero out loud. Both renderings are one state and one file, so the dashed row below switches between them and nothing inside the screen does.
