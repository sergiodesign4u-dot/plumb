Delivery, not recruitment

The node where a number leaves one person and reaches another, and the third of the four capabilities the first test needs. Without it the card reaches nobody and the product is a page with no reason to be opened. Everything that looks like growth has been refused here on purpose.

Type: dialog Scope: MVP Opens from node 2.1 Source: ia/docs/pages/send.md
01

Why a dialog and not just a button

A copy-link button with a toast would be smaller, and it was the obvious first answer. The dialog earns its place on one argument: you should be able to see what you are passing on.

  1. The link is visible and selectable, which is the failure route when the clipboard is unavailable. Node 0.3 already named that fallback.
  2. For a trust product, seeing what you are about to send is not decoration. The whole premise is that a number should not travel without its provenance, and a person handing one on can reasonably want to look at what leaves their hands.

No URL of its own, and the contrast with node 2.7 is deliberate. The source layer is addressable because it is content somebody would want to link to. This is a transient action with nothing to return to. The rule is not that everything gets a URL. It is that anything worth linking to gets one, and a send dialog is a door, not a room.

03

The decision inside the link

What is copied: /m/<stable-id>?v=<definition-version>&t=<sent-at>. The stamp is taken when Send is pressed, not when the page was opened, because the sender is handing on what they are looking at now.

The forwarding decision, which no earlier artefact had

A reader who received a link and presses Send mints a new one, stamped from their own reading. They do not propagate the stamp they received.

The alternative fails on its own terms. State 2.5 answers "has the definition changed since you read this", and "you" has to mean the person who sent it, not a stranger three hops back. A chain carrying the first stamp forever would tell the fifth recipient about a change that happened before four other people had already looked and been satisfied.

The honest cost, stated rather than hidden. If the sender saw the "definition changed" state and forwards anyway, that state does not travel: the recipient gets a clean card stamped now. The changed state is a fact about a reading, not a property of the number, and it belongs to whoever did the reading. If it matters, it is theirs to say.

What we do not control: somebody pasting a URL by hand. That is copy and paste rather than this node, and pretending otherwise would be designing for an act we cannot observe.

05

States, the canonical dialog, and a question closed

StateWhat happens
OpenThe link is visible and selected on open, so a keyboard user can copy without hunting
CopiedToast from node 0.3, auto-dismissing because nothing is lost: the link is in the clipboard and still on screen
Clipboard unavailableNo error toast. The link is on screen and selectable, so the fallback is already in view
Sending a card whose source is downAllowed, and the link works. The recipient gets the same honest state. Nothing is blocked here because the number is inconvenient
An open question from node 0.3, now closed

0.3 asked whether a reader ever needs a failure toast at all. The answer is no, and the reason is block 2: the link is on screen before anything is copied, so a clipboard failure has its fallback already visible. The reader's half of the feedback component is a single success message, and the assertive announcement path is analyst-only. Node 0.3 has been amended in both its source and its page.

This node defines the canonical dialog. Focus is trapped, Escape closes, focus returns to the trigger, targets are 44 by 44 CSS pixels. Later nodes that need a dialog reference this rather than restating it.

Emotional support: one mechanism lands here, and the table already calls it thin. P1 social, be seen as somebody who checks rather than somebody who forwards, supported only by the fact that provenance travels with the number. The table marks that job [?] throughout and the mark is kept: nothing in the research says anybody wants to be seen this way. If the job turns out to be imaginary, nothing on this page changes, because the same block also serves R2, which is evidenced.
