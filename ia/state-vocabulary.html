Three states, no fourth, and none of them needs a hover to exist

A canonical list rather than a screen. The same three states are consumed by the card, by the rows of the registry and by the definition editor, and a product whose whole claim is that a number means one thing cannot afford to be ambiguous about its own states.

Type: section Scope: MVP Source: ia/docs/pages/state-vocabulary.md
01

Why this is a node

The three states are consumed by the card and its state nodes, the rows of the registry, and the definition editor. If the vocabulary is not canonical it drifts, and it drifts in the most damaging direction available here: the registry starts saying "stale", the card says "out of date" and the editor says "changed". One list, one wording, one set of rules for when each applies, and every screen references this node rather than restating it.

The vocabulary

There is no fourth state, and "Healthy" is not one of them

A number with nothing wrong carries its age, not a badge saying it is fine. Saying a number is healthy is a claim we would have to defend; showing when it was computed is a fact.

03

What this vocabulary refuses

  • No severity. A state is not high, medium or low. Severity implies triage, triage implies a queue, and a queue is the incident tool we refused to build.
  • No assignee and nothing to close. A state ends when the underlying fact ends.
  • No aggregate. No health percentage, no trust score, no "99.4% reliable". A score cannot be interrogated, so it replaces one number nobody can defend with a second one.
  • No colour-only encoding. Every state is legible in words with the colour removed, which is both an accessibility requirement and the reason these survive a black and white wireframe.
  • No collapsing into a worst-case indicator. Two true things stay two true things.

Where each state appears

SurfaceHow it appears
The card (2.1)In full, in words, beside the value. The primary place
Registry rows (4.1)Compact: the state name and the age, no explanation. The row links to the card, where the full form lives
Definition editor (4.7)As a consequence: "changing this will put the changed state on cards already sent"
Search results (4.3)The same compact form as the registry

The compact form is a shortening, never a different vocabulary. Same words, fewer of them.

Accessibility

  • Never colour alone: text carries the state, and colour, when the visual stage adds it, is redundant reinforcement.
  • Live regions do not apply. A state is present on load rather than announced as an event, which is the same distinction the feedback node draws between a state and a toast.
  • Screen readers get the state before the value in the reading order on the card, because a value read without its state is exactly the bare number this product exists to prevent.
Two open questions this node hands forward

What "expected hourly" says when no cadence is known. Not every source declares one, and "as of 14:05" with no expectation beside it is the failure the benchmark mechanism was taken to prevent.

How old is old. Nothing here decides when "as of" should start looking uncomfortable, and the honest answer is that it depends on the metric's cadence rather than on a fixed threshold. It stays open rather than being invented.
